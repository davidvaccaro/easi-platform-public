Stream Lifecycle

This page is the detailed callback and status reference for the EASI stream protocol. Use Stream Processing Model for the conceptual overview; use this page for exact lifecycle vocabulary, event ordering constraints, and status behavior.

Reference Scope

Page Boundary

Stream Processing Model explains why streaming is fundamental and how parser and handler stages cooperate. Stream Lifecycle defines what callback names, ordering, and status semantics must be preserved for conformance.

Canonical Event Vocabulary

Phase Representative Events Normative Expectation
Instance Start onStartInstance Must initialize parse scope/context for one instance payload.
Container Start onStartMetaSet, onStartDataSet, onStartSequence, onStartItem Must preserve nesting semantics and stack safety.
Element Start/Append/End onStartAttribute, onAppendAttribute, onEndAttribute Must respect incremental element completeness and deterministic ordering.
Container End onEndItem, onEndSequence, onEndDataSet Must close nesting scopes in strict LIFO order.
Instance End onEndInstance Must finalize one output contract and release scoped state.

Status Contract

Canonical parser status vocabulary:

Status Meaning Typical Parser Behavior
CONTINUE Keep normal parse progression. Continue reading bytes/events in current context.
SUCCESS Current operation completed successfully. Commit result and continue outer progression.
STOP Terminate parse intentionally. Stop processing and return current final state.
JUMP Skip current subtree/segment. Fast-forward to matching structural boundary.
FAIL Fatal parse/contract failure. Abort parse, surface structured error condition.

Lifecycle Ordering and Determinism

Required Invariants

1. Event order for a given input MUST be deterministic.
2. Status handling MUST be deterministic and side-effect safe.
3. JUMP semantics MUST skip exactly the targeted subtree scope.
4. End events MUST NOT be emitted before matching start events.

Implementation Guidance

Async scheduling MAY differ by language runtime, but externally observable event sequence and status outcomes should remain stable under equivalent inputs.

Conformance Checklist

What Must Stay Stable

1. Start/end callbacks must remain structurally paired under nested sequence/item depth.
2. Status return values must be interpreted consistently regardless of language runtime.
3. JUMP and SKIP behavior must only affect the intended subtree scope.
4. Result finalization should occur only after a valid onEndInstance boundary.
