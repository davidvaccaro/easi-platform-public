Pipeline Writing

Writers package terminal output to concrete destinations (file, stream, HTTP, DIMSE, archive) while keeping terminal semantics stable and transport concerns isolated.

Writer Role

Writers are the final transport boundary. They SHOULD translate semantic terminal output into destination-specific payloads without redefining parser/filter/terminal contracts.

Normative Requirement

Writer layers MUST preserve terminal output semantics and MUST return deterministic operation results, exposed through PipelineResultCollection and writer result envelopes.

Common Writer Targets

Builder Surface Destination Type Typical Use
intoFileStream() Filesystem path Persistent local or mounted archive output.
intoWritableStream() Writable stream abstraction In-process streaming to adapters and custom sinks.
intoHttpStream(...) HTTP endpoint REST, custom HTTP ingest, and STOW-RS profile-safe writes.
intoDimseAssociation(...) DIMSE association C-STORE relay and DIMSE-native distribution flows.

Destination Binding Modes

EASI writing pipelines can bind source and destination at build-time, process-time, or a mix. The mode below is defined by how from* and into* are composed.

Mode Builder Shape Typical process(...) Form Best Fit
Early-Bound from*(source) and into*(destination) process() Fully pre-wired pipelines with fixed source and fixed destination.
Late-Bound from*() and into*() process(source, destination) Reusable pipelines where both source and destination vary per run.
Hybrid from*() and into*(destination) process(source) Reusable source with a fixed operational destination route.

If a destination is bound in the pipeline, callers can still provide a process-time destination to override it for one transaction.

Usage

Language-Neutral Examples

Late-bound mode (source and destination both late-bound).

lateBoundPipeline := EASI.pipelineBuilder()
  .fromFileStream()
  .ofDicomData()
  .withDeIdentification(Tag.DefaultDeIdentificationMask)
  .toDicomData()
  .intoFileStream()
  .build()

lateBoundResults := lateBoundPipeline.process(sourcePath, destinationPath)
lateBoundWrite := lateBoundResults.first()
bytesWritten := lateBoundWrite.bytesWritten

Hybrid mode (source late-bound, destination early-bound).

hybridPipeline := EASI.pipelineBuilder()
  .fromHttpStream()
  .ofDicomData()
  .withTranscoding(TransferSyntax.ExplicitVRLittleEndian.ID)
  .toDicomData()
  .intoHttpStream("https://pacs.example.org/dicom-web/studies", {
    method: "POST",
    headers: { "Content-Type": "application/dicom" }
  })
  .build()

hybridResults := hybridPipeline.process(sourceUrl)
hybridWrite := hybridResults.first()
status := hybridWrite.status

Early-bound mode (source and destination both bound at build-time).

earlyBoundPipeline := EASI.pipelineBuilder()
  .fromHttpStream(sourceUrl)
  .ofDicomData()
  .withTranscoding(TransferSyntax.ExplicitVRLittleEndian.ID)
  .toDicomData()
  .intoHttpStream("https://pacs.example.org/dicom-web/studies", {
    method: "POST",
    headers: { "Content-Type": "application/dicom" }
  })
  .build()

earlyBoundResults := earlyBoundPipeline.process()
earlyBoundWrite := earlyBoundResults.first()

Writer Design Notes

  • Return stable, documented operation result envelopes.
  • Treat transport retries/failures as writer-level concerns.
  • Keep destination options explicit and profile constrained when standards apply.
  • Avoid leaking transport details back into parser/filter/mapping layers.
