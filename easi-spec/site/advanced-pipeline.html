Advanced Pipeline Use Cases

This page demonstrates how one EASI pipeline model can power advanced, production-style DICOM® workflows across ingestion, transformation, routing, and non-DICOM® asset extraction.

Informative page: real-world scenario patterns intended to prove breadth and composability.

Practical Goal

Show that EASI pipelines are not only parser wrappers. They can serve as the execution core for imaging gateways, retrieval services, migration utilities, de-identification processors, and mixed DICOM®/cloud asset workflows.

Advanced Pattern Map

Scenario Family Typical Pipeline Primitives Operational Outcome
Inbound Bridge Service fromDimseAssociation + start() + toAssets Continuous C-STORE ingestion with immediate metadata/frame/content extraction.
Query + Retrieve Relay fromDimseAssociation + toInstances + intoDimseAssociation Selective C-FIND/C-MOVE orchestration and controlled forwarding.
Bulk DICOMweb™ Migration fromHttpStream + withValidation + withTranscoding + intoFileStream Large-scale normalization of mixed source archives into a target transfer syntax.
Privacy-First Processing withDeIdentification + withBurnedInRedaction Consistent metadata and burned-in text cleanup in one deterministic flow.
Custom HTTP Integration toDicomData + intoHttpStream Push transformed output into proprietary APIs with custom method/header contracts.
STOW-RS DICOMweb™ Store withTranscoding + intoHttpStream(..., { stow: true }) Constrained STOW-safe upload semantics on top of the generic HTTP writer.

Operational Controls

Lifecycle Control

Use process(source) for one-shot transactions and start()/stop() for source-bound listeners.

Result Contract

Pipeline terminal results are normalized to PipelineResultCollection for stable cardinality handling.

Error Strategy

Use continueOnError, onError, and concern callbacks to preserve service uptime during noisy traffic.

Iteration Guardrails

Use maxIterations and cancellation signals for safe job and listener lifecycle control.

Advanced Use-Case Gallery

Each scenario below is intentionally end-to-end. The goal is to make it obvious that EASI can be the runtime core for practical, advanced DICOM® processing services.

Language-Neutral Examples

Scenario: C-STORE listener bridge with de-identification, strict US redaction, and cloud asset push.

listenerAssociation := { host: "0.0.0.0", port: 11112, calledAeTitle: "EASI_BRIDGE" }

bridgePipeline := EASI.pipelineBuilder()
  .fromDimseAssociation(listenerAssociation, NodeDimseCStoreScpSourceTransport)
  .ofDicomData()
  .withDeIdentification(Tag.DefaultDeIdentificationMask)
  .withBurnedInRedaction({
    mode: "regions",
    regions: [
      { x: 24, y: 10, width: 220, height: 40 },
      { x: 24, y: 54, width: 260, height: 30 }
    ]
  })
  .toAssets({
    metadata: {
      mapping: DicomToFHIRImagingStudyMapping({ profile: "study-summary" }),
      collect: true
    },
    payload: {
      frame: { frames: "first", decode: "rgba", encode: "png" },
      collect: true
    }
  })
  .build()

run := bridgePipeline.start(null, {
  onResult: (resultCollection, context) => {
    assets := resultCollection.first()
    cloud.putJSON("/ingest/" + context.iterations + "/metadata", assets.metadata)
    cloud.putBinary("/ingest/" + context.iterations + "/frame-1.png", assets.frames[0].bytes)
    return true
  }
})

Scenario: query-first selective retrieve and relay to a destination archive.

queryPipeline := EASI.pipelineBuilder()
  .fromDimseAssociation(sourceAssociation, NodeDimseQueryRetrieveSourceTransport)
  .ofDicomData()
  .toInstances()
  .build()

relayPipeline := EASI.pipelineBuilder()
  .fromDimseAssociation(sourceAssociation, NodeDimseQueryRetrieveSourceTransport)
  .ofDicomData()
  .withTranscoding(TransferSyntax.ExplicitVRLittleEndian.ID)
  .toDicomData()
  .intoDimseAssociation(destinationAssociation, { transport: NodeDimseCStoreScuTransport })
  .build()

matches := queryPipeline.process({ operation: "cfind", level: "IMAGE", keys: { Modality: "CT" } })
for each match in matches:
  relayPipeline.process({
    operation: "cmove",
    level: "IMAGE",
    destinationAeTitle: destinationAssociation.calledAeTitle,
    keys: { SOPInstanceUID: match.dataSet.value(Tag.SOPInstanceUID) }
  })

Scenario: bulk DICOMweb™ migration with normalization to a target transfer syntax.

migrationPipeline := EASI.pipelineBuilder()
  .fromHttpStream()
  .ofDicomData()
  .withValidation("strict")
  .withTranscoding(TransferSyntax.ExplicitVRLittleEndian.ID)
  .toDicomData()
  .intoFileStream("/archive/normalized/{instanceUID}.dcm")
  .build()

for each sourceUrl in manifest.urls:
  migrationPipeline.process(sourceUrl, { continueOnError: true })

Scenario: local DICOM® de-identification followed by upload to a custom HTTP host.

sourcePath := "/var/easi/inbox/ct/CT-001.dcm"

customUploadPipeline := EASI.pipelineBuilder()
  .fromFileStream()
  .ofDicomData()
  .withDeIdentification(Tag.DefaultDeIdentificationMask)
  .toDicomData()
  .intoHttpStream({
    url: "https://custom-host.example.com/imaging/upload",
    method: "PUT",
    headers: {
      Authorization: "Bearer {token}",
      "X-Tenant": "acme-imaging",
      "Content-Type": "application/vnd.acme.dicom-binary"
    }
  }, {
    stream: false
  })
  .build()

customUploadCollection := customUploadPipeline.process(sourcePath)
customUploadResult := customUploadCollection.first()
customStatus := customUploadResult.status

Scenario: read, transcode, and POST to a STOW-RS endpoint using STOW-safe HTTP options.

sourceUrl := "https://source.example.com/dicom-web/studies/{studyUID}/series/{seriesUID}/instances/{instanceUID}"

stowPipeline := EASI.pipelineBuilder()
  .fromHttpStream()
  .ofDicomData()
  .withTranscoding(TransferSyntax.ExplicitVRLittleEndian.ID)
  .toDicomData()
  .intoHttpStream({
    url: "https://pacs.example.com/dicom-web/studies",
    headers: {
      Authorization: "Bearer {token}"

    stow: true,
    stream: false
  })

stowCollection := stowPipeline.process(sourceUrl)
stowResult := stowCollection.first()
