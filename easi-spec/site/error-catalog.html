Error Catalog

This page defines canonical EASI failure and concern families so implementations can report compatible diagnostics without requiring identical exception class names.

Concern Model

Field Description Normative Guidance
category High-level concern family. Implementations SHOULD use catalog categories.
code Stable symbolic code for machine handling. Codes MUST be stable across minor releases.
message Human-readable summary. MAY be localized; must preserve intent.
severity Diagnostic impact (info, warning, error, fatal). Severity escalation rules SHOULD be documented.
context Operation, stage, and source metadata. SHOULD include enough context for triage and replay.

Canonical Categories and Codes

Category Representative Codes Typical Trigger
Build BuildMissingParser, BuildMissingTerminal, BuildIncompatibleDestination Invalid pipeline composition during build().
Compatibility UnsupportedTerminalForParser, UnsupportedTransferSyntaxPair, PresentationContextRejected Parser/output/transport mismatch at build or runtime.
Parse MalformedElement, UnexpectedEndOfStream, InvalidLength, InvalidTagEncoding Byte or metadata input cannot satisfy parser invariants.
Lifecycle UnexpectedEndEvent, UnbalancedNesting, InvalidStatusTransition Lifecycle contract violation in parser/handler chain.
Validation MissingRequiredAttribute, InvalidValueRepresentation, PolicyViolation Validation filter identifies semantic non-conformance.
DeIdentification MaskConflict, UnsupportedReplacementMode, RedactionRegionInvalid De-identification policy cannot be safely applied.
Transport AssociationOpenFailed, AssociationClosedUnexpectedly, Timeout Connection/session lifecycle failures.
Protocol SourceOperationFailed, StoreOperationFailed, ProtocolStateViolation DIMSE or transport-protocol operation failure.

Status and Error Relationship

FAIL

Represents a terminal condition. A structured concern or exception payload must accompany pipeline failure.

STOP

Represents intentional, non-failure termination. Should not be mapped to a fatal error unless contract conditions are violated.

JUMP

Represents controlled subtree skipping. If skip target cannot be resolved, surface a lifecycle or parse concern.

Warnings

Non-fatal concerns may accumulate while output remains valid; implementations should expose concern collections consistently.

Recommended Concern Payload (Illustrative)

{
  "category": "Parse",
  "code": "UnexpectedEndOfStream",
  "severity": "fatal",
  "message": "End of stream reached before closing sequence delimiter.",
  "context": {
    "stage": "parser",
    "offset": 1048576,
    "tag": "fffe,e0dd"
  }
}

Interoperability Rule

Implementations MAY use runtime-specific exception types, but they SHOULD preserve canonical category and code semantics so monitoring, retries, and conformance tools can reason across languages.
