Pipeline Reader

Readers define the ingress boundary for pipeline processing by binding a source and producing a stream abstraction that can be consumed incrementally by the parser stage.

Purpose

Use reader surfaces to define where source data comes from (file, HTTP, stream, folder) and how source binding occurs (early-bound, late-bound, or hybrid). The reader stage is responsible for transport concerns, not semantic interpretation.

Normative Requirement

Reader implementations MUST preserve ordered byte delivery and MUST expose deterministic completion/error behavior for each source transaction.

Core Concepts

Concept Core EASI Semantics
Source Binding Sources may be bound during composition (early-bound) or supplied at process(...) time (late-bound).
Ingress Framing Readers normalize ingress framing (single-part, multipart, stream chunks) before parser semantics begin.
Streaming Discipline Reader behavior is stream-first and SHOULD avoid full-buffer loading when incremental processing is possible.
Source Metadata Reader surfaces may attach transport metadata (content-type, boundary, source identity) for downstream stage decisions.
Reader/Parser Contract Reader output feeds parser input; semantic decisions are deferred until parser handlers materialize stage-aware state.

Builder Surface

Builder Surface Typical Source Core Role
fromFileStream(...) Filesystem path or file handle Read native file-based DICOM® payloads.
fromHttpStream(...) HTTP endpoint / URL Read over HTTP(S), including DICOMweb™ responses.
fromPartStream(...) Multipart / mixed payload stream Normalize part boundaries for parser ingestion.
fromFolderStream(...) Directory-based source stream Process file collections as a staged stream workload.
fromFolderWatcher(...) Filesystem watch source Reactively process new arrivals from watched ingestion folders.

Usage

Reader declarations focus on ingress and binding semantics. Parsing and terminal contracts remain independent and are selected by downstream stages.

Language-Neutral Examples

Late-bound source over HTTP stream ingress.

pipeline := EASI.pipelineBuilder()
  .fromHttpStream()
  .ofDicomData()
  .toInstances()
  .build()

resultCollection := pipeline.process(sourceUrl)
instance := resultCollection.first()

Folder watcher source for continuous ingestion.

watchPipeline := EASI.pipelineBuilder()
  .fromFolderWatcher({
    path: "/var/easi/inbox",
    pattern: "*.dcm",
    debounceMs: 250
  })
  .ofDicomData()
  .toEntities()
  .build()

watchResults := watchPipeline.process()

Reader Design Notes

  • Keep transport concerns in reader surfaces; keep semantic logic in parser/terminal stages.
  • Prefer late-bound source patterns for highly reusable pipeline definitions.
  • Use folder stream/watcher ingress for batch and continuous ingestion workloads.
  • Document source error semantics so operational retries remain deterministic.
