Pipeline Parser

Parsers convert ingress byte streams into deterministic lifecycle semantics that drive terminals, filters, mappings, and selection contracts.

Purpose

The parser stage defines how data is interpreted after reader ingress. It materializes state progressively (meta, data, attributes, values) and emits canonical events used by downstream contracts.

Normative Requirement

Parser implementations MUST preserve lifecycle ordering and MUST expose stable status transitions for a given byte sequence and parser profile.

Core Concepts

Concept Core EASI Semantics
Parser Profile Profile selection (for example DICOM data vs metadata) controls which semantic structures are emitted downstream.
Lifecycle Events Canonical event boundaries (container, attribute, value) provide deterministic extension points for handlers and terminals.
Status Flow Parsers expose status progression so routing, filtering, and completion logic can stay stage-safe and predictable.
Progressive Materialization Semantic state can be consumed incrementally without requiring full object graph materialization up front.
Custom Parsing Custom parser implementations may be attached with withParser(...) while preserving canonical lifecycle expectations.

Builder Surface

Builder Surface Parser Focus Typical Use
ofDicomData() MetaSet + DataSet semantics Full semantic interpretation for processing and writing flows.
ofDicomMetadata() Metadata-focused parse profile Metadata-first indexing, validation, and routing workloads.
ofDicomXmlMetadata() DICOM XML metadata representation XML profile interoperability and metadata transformation flows.
withParser(customParser) Explicit parser override Custom or profile-specific parse behavior with standard terminal contracts.

Usage

Parser stage declarations define semantic interpretation boundaries; downstream terminal choice defines materialization and output contracts.

Language-Neutral Examples

Metadata-first parsing with selection terminal output.

selection := EASI.selectionBuilder()
  .include([Tag.StudyInstanceUID, Tag.SeriesInstanceUID, Tag.Modality])
  .build()

pipeline := EASI.pipelineBuilder()
  .fromPartStream()
  .ofDicomMetadata()
  .toSelection(selection)
  .build()

selectionResults := pipeline.process(source)
metadata := selectionResults.first()

Custom parser attachment using explicit parser surface.

pipeline := EASI.pipelineBuilder()
  .fromHttpStream()
  .withParser(customParser)
  .toMapping(customMapping)
  .build()

Parser Design Notes

  • Choose the narrowest parser profile that still satisfies downstream contract needs.
  • Keep parser responsibilities focused on interpretation, not destination delivery.
  • Document parser status/event assumptions when introducing custom parser profiles.
  • Align routing predicates with the stage where required semantic state is available.
