Pipeline Mappings

Mappings define deterministic projection from parsed DICOM® semantics into domain-specific output shapes (for example FHIR® resources or custom business objects) while preserving stream lifecycle boundaries.

Purpose

Use mappings when the caller needs semantic output instead of native DICOM® object model materialization. A mapping receives parser lifecycle callbacks through the terminal handler chain and emits final projection output at end-of-transaction boundaries.

Normative Requirement

Mapping implementations MUST remain deterministic for the same input stream and MUST NOT violate lifecycle ordering semantics established by parser status transitions.

Typical Composition

Reader -> Parser -> [Adapter] -> [Filter ...] -> Mapping Terminal -> [Writer]
Builder Surface Description
toMapping(mapping) Bind one custom mapping implementation.
toFHIRImagingStudy(options) Bind the built-in DICOM® to FHIR® ImagingStudy mapping profile.
EASI.mappingBuilder() Compose custom mapping contracts with declarative mapping builders.

Usage

Mapping terminals return one PipelineResultCollection per transaction. The first() item is the mapping contract output (for example one FHIR® ImagingStudy or one custom routing object).

Language-Neutral Examples

Typical use case: map to FHIR® ImagingStudy study-summary output.

studySummaryMapping := DicomToFHIRImagingStudyMapping({ profile: "study-summary" })

pipeline := EASI.pipelineBuilder()
  .fromHttpStream()
  .ofDicomData()
  .toMapping(studySummaryMapping)
  .build()

resultCollection := pipeline.process(sourceUrl)
if resultCollection.isEmpty:
  fail("Expected one ImagingStudy mapping result")
imagingStudy := resultCollection.first()
studyIdentifier := imagingStudy.identifier[0].value

Real-world use case: map recognizable DICOM® tags to an operational routing card.

class RoutingCardMapping extends DicomMapping
  constructor():
    super()
    EASI.mappingBuilder()
      .withMapping(this)
      .withTemplatePolicy("omit")
      .withProperty("routeBase", "dicom-ingest")
      .map(Tag.StudyInstanceUID, "card.study.uid")
      .map(Tag.SeriesInstanceUID, "card.series.uid")
      .map(Tag.SOPInstanceUID, "card.instance.uid")
      .map(Tag.PatientID, "card.patient.id")
      .map(Tag.Modality, "card.classification.modality")
      .map(Tag.BodyPartExamined, "card.classification.bodyPart")
      .map(Tag.InstanceNumber, "card.instance.number", { transform: toInteger })
      .withComputed("card.route.key", { template: "{dicom.Modality}|{dicom.StudyInstanceUID}|{dicom.SeriesInstanceUID}" })
      .withComputed("card.route.path", { template: "{prop.routeBase}/{dicom.Modality}/{dicom.StudyInstanceUID}/{dicom.SeriesInstanceUID}" })
      .build()

  start(context):
    super.start(context)
    context.card := {
      study: {},
      series: {},
      instance: {},
      patient: {},
      classification: {},
      route: {}
    }
    return context

  end(context):
    super.end(context)
    return context.card

routingPipeline := EASI.pipelineBuilder()
  .fromFileStream()
  .ofDicomData()
  .toMapping(RoutingCardMapping())
  .build()

routingResults := routingPipeline.process(sourcePath)

  fail("Expected one routing card")

Real-world use case: map recognizable DICOM® tags to an operational routing card.

class RoutingCardMapping(DicomMapping):
    def __init__(self):
        super().__init__()
        (
            EASI.mapping_builder()
            .with_mapping(self)
            .with_template_policy("omit")
            .with_property("routeBase", "dicom-ingest")
            .map(Tag.study_instance_uid, "card.study.uid")
            .map(Tag.series_instance_uid, "card.series.uid")
            .map(Tag.sop_instance_uid, "card.instance.uid")
            .map(Tag.patient_id, "card.patient.id")
            .map(Tag.modality, "card.classification.modality")
            .map(Tag.body_part_examined, "card.classification.bodyPart")
            .map(Tag.instance_number, "card.instance.number", {
                "transform": lambda value: int(value) if str(value).isdigit() else None
            })
            .with_computed("card.route.key", {
                "template": "{dicom.Modality}|{dicom.StudyInstanceUID}|{dicom.SeriesInstanceUID}"
            })
            .with_computed("card.route.path", {
                "template": "{prop.routeBase}/{dicom.Modality}/{dicom.StudyInstanceUID}/{dicom.SeriesInstanceUID}"
            })
            .build()
        )

    def start(self, context):
        context = super().start(context)
        context.card = {
            "study": {},
            "series": {},
            "instance": {},
            "patient": {},
            "classification": {},
            "route": {}
        }
        return context

    def end(self, context):
        super().end(context)
        return context.card

Authoring Checklist

  • Keep projection logic pure with respect to input lifecycle state.
  • Handle multi-part or repeated emit boundaries without duplicate finalization.
  • Define clear completion semantics for partial input and missing tags.
  • Document expected output contract and cardinality.
