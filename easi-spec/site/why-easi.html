Advantages of EASI

EASI gives developers a practical way of orchestrating modern DICOM® workflows without absorbing the full complexity of native DICOM® data processing and communications. It abstracts dense DICOM protocol-stack details (DIMSE/DICOMweb™ transport plus DICOM® encoding/parsing semantics) behind a fluent, language-neutral DSL that is easier to compose, verify, automate, and maintain.

Adoption Pitch

If your project touches medical imaging information, an EASI approach reduces development friction immediately: clearer composition, reusable contracts, deterministic event-driven stream processing semantics, and stronger AI agentic fluency for implementation and maintenance. EASI is not a cosmetic API layer, it is an operational model for building and generating more reliable and maintainable modern DICOM® workflows.

Why EASI is better

Project Need EASI Response Practical Effect
Readable processing logic Staged fluent contract (from -> of -> with -> to -> into) New engineers and reviewers understand intent quickly.
One model for many workflows Same pipeline shape across file, HTTP, DICOMweb™, DIMSE and bespoke Less architectural drift and fewer bespoke one-off flows.
Privacy and policy controls In-band de-identification, validation, filtering, redaction, transcoding Policy enforcement becomes composable and testable.
Streaming-first behavior Deterministic, event-driven parser-lifecycle model with materialization control Scales better for large studies and real-time ingestion paths.
AI-assisted implementation Low-ambiguity stage vocabulary and explicit contracts Higher-quality agentic code generation and maintenance.

Real-World Use Cases

The examples below start with a simple reader and build toward production-grade workflows. Each tab shows the same scenarios in a language-neutral and language-specific form.

1) Read one instance for immediate business logic

sourcePath := "/ingest/inbox/ct/CT-001.dcm"

// Compose an EASI pipeline that reads from a file source, 
// parses native-DICOM and produces a result EASI "Instance"

readerPipeline := EASI.pipelineBuilder()
  .fromFileStream()
  .ofDicomData()
  .toInstances()
  .build()

// Process the source DICOM file
resultCollection := readerPipeline.process(sourcePath)

// Access the result Instance
instance := resultCollection.first()

// Use the Instance to read the DICOM Study Instance UID attribute value
studyUid := instance.dataSet.value(Tag.StudyInstanceUID)

2) Apply de-identification and produce compliant outbound DICOM®

sourcePath := "/ingest/inbox/ct/CT-001.dcm"
destinationPath := "/egress/deidentified/CT-001.dcm"

// Compose an EASI pipeline that reads from a file source,
// parses native-DICOM, de-identifies "in-flight" using 
// the standard de-identification mask, then serializes 
// to native-DICOM and stream writes the result bytes out 
// to a destination file

deIdPipeline := EASI.pipelineBuilder()
  .fromFileStream()
  .ofDicomData()
  .withDeIdentification(Tag.DefaultDeIdentificationMask)
  .toDicomData()
  .intoFileStream()
  .build()

// Process the source DICOM file into a destination DICOM file
writeResults := deIdPipeline.process(sourcePath, destinationPath)

// Access the result of the operation and check the conversion status
writeResult := writeResults.first()
if (writeResult.bytesWritten <= 0):
  fail("Expected de-identified output bytes")

3) Convert DICOMweb™ metadata retrieval into FHIR® ImagingStudy resources

studyMetadataUrl := "https://pacs.example.org/dicom-web/studies/{studyUID}/metadata"

// Compose an EASI pipeline that reads from an DICOMweb host,
// parses DICOM JSON metadata and produces a FHIR ImagingStudy resource

imagingStudyPipeline := EASI.pipelineBuilder()
  .fromHttpStream()
  .ofDicomMetadata()
  .toFHIRImagingStudy("full")
  .build()

// Process the source DICOMweb metadata
imagingStudyResults := imagingStudyPipeline.process(studyMetadataUrl)

// Access the result FHIR Imaging Study
imagingStudy := imagingStudyResults.first()

4) Run an inbound DIMSE C-STORE listener and relay normalized output

// Compose an EASI pipeline that listens for inbound C-STORE requests, 
// parses native-DICOM, de-identifies "in-flight" using 
// the standard de-identification mask, then serializes 
// to native-DICOM and HTTP POSTs the result bytes as a STOW-RS transaction 
// to a remote DICOMweb or bespoke cloud host.

listenerPipeline := EASI.pipelineBuilder()
  .fromDimseAssociation({
    role: "scp",
    host: "0.0.0.0",
    port: 4104,
    calledAET: "IMAGEBRIDGE"
  })
  .ofDicomData()
  .withDeIdentification(Tag.DefaultDeIdentificationMask)
  .toDicomData()
  .intoHttpStream("https://cloud.example.org/dicom-web/studies", {
    method: "POST",
    stow: true
  })
  .build()

// Start the pipeline listening for inbound requests
run := listenerPipeline.start()

// ... pipeline runs continuously ...

// Stop the pipeline 
run.stop()

Why This Is A Meaningful Shift For DICOM® Orchestration

EASI keeps DICOM® at the core while making sophisticated workflow orchestration much simpler to compose, understand, and maintain thereby reducing friction and expanding where DICOM® workflows are practical in modern application architectures.
