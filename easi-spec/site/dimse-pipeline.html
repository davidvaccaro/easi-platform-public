DIMSE Pipelines

This page defines how EASI composes DIMSE operations into the same fluent pipeline model, including request/response query-retrieve flows and source-bound listener lifecycles.

DIMSE Operation Map

.withAssociation(...)

.fromDimseAssociation(...)
.ofDicomData()
.toInstances()
.build()
.start({ onResult: ... })

Execution Modes

Transactional

Caller supplies one DIMSE request payload via source options and expects one result collection.

resultCollection = pipeline.process({ sourceOptions: request })

Source-Bound Listener

Source is already bound by transport/association (for example inbound C-STORE SCP).

run = pipeline.start({ onResult: ... })

Listener Semantics

In listener mode, the DIMSE source is the configured association + transport. The pipeline waits for inbound data and invokes onResult per transaction. Stop with run.stop() or pipeline.stop().

DIMSE Use-Case Gallery

The examples below show practical DIMSE workflows and highlight the difference between request/response process(...) operations and long-running start() listeners.

Language-Neutral Examples

Typical use case: verify DIMSE endpoint reachability (C-ECHO).

association := EASI.dimseAssociationBuilder()
  .withHost("127.0.0.1")
  .withPort(4242)
  .withCallingAeTitle("EASI_JS")
  .withCalledAeTitle("ORTHANC")
  .build()

client := EASI.dimseClientBuilder()
  .withAssociation(association)
  .build()

echoResult := client.echo()

Real-world use case: C-FIND study discovery returned as native DICOM® instances.

findSourceAssociation := {
  host: "127.0.0.1",
  port: 4242,
  callingAeTitle: "EASI_JS",
  calledAeTitle: "ORTHANC"
}

findPipeline := EASI.pipelineBuilder()
  .fromDimseAssociation(findSourceAssociation, NodeDimseQueryRetrieveSourceTransport)
  .ofDicomData()
  .toInstances()
  .build()

findRequest := {
  operation: "c-find",
  queryRetrieveLevel: "STUDY",
  keys: { Modality: "CT" }
}

instanceCollection := findPipeline.process({ sourceOptions: findRequest })
instances := instanceCollection.toArray()

Real-world use case: C-MOVE source with in-flight de-identification and C-STORE relay.

moveSourceAssociation := { host: "127.0.0.1", port: 4242, callingAeTitle: "EASI_JS", calledAeTitle: "ORTHANC" }
moveDestinationAssociation := { host: "127.0.0.1", port: 4242, callingAeTitle: "EASI_JS", calledAeTitle: "ORTHANC" }

relayPipeline := EASI.pipelineBuilder()
  .fromDimseAssociation(moveSourceAssociation, NodeDimseQueryRetrieveSourceTransport)
  .ofDicomData()
  .withDeIdentification(Tag.DefaultDeIdentificationMask)
  .toDicomData()
  .intoDimseAssociation(moveDestinationAssociation, { transport: NodeDimseCStoreScuTransport })
  .build()

relayPipeline.process({ sourceOptions: {
  operation: "c-move",
  queryRetrieveLevel: "IMAGE",
  moveDestinationAeTitle: "EASI_MOVE_DEST",
  keys: { StudyInstanceUID: "{studyUID}" }
} })

Real-world use case: inbound C-STORE SCP listener using start() (no process()).

listenerAssociation := {
  host: "0.0.0.0",
  port: 11112,
  calledAeTitle: "EASI_STORE"
}

listenerPipeline := EASI.pipelineBuilder()
  .fromDimseAssociation(listenerAssociation, NodeDimseCStoreScpSourceTransport)
  .ofDicomData()
  .toInstances()
  .build()

run := listenerPipeline.start({
  onResult: (resultCollection, context) => {
    instance := resultCollection.first()
    log("received instance #" + context.iterations)
    return true
  }
})

... wait for inbound C-STORE traffic ...

run.stop()
await run.done
