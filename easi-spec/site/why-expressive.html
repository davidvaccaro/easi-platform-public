Why Expressive?

EASI utilizes an expressive design pattern that makes the intent of complex DICOM® orchestrations clear and intuitive. Far from being a mere stylistic choice, the EASI fluent builder scheme employs a staged design that enforces strict compositional guardrails. This architecture ensures high reliability, making sophisticated imaging workflows accessible to general developers and agentic coding environments alike.

Core Advantage

Expressiveness allows a developer to consolidate five distinct processing primitives into a single, cohesive declaration. In one clear statement, EASI defines the entire lifecycle of a complex orchestration:

  • FROM: (Ingestion) Where the data originates?
  • OF: (Parsing) How the data is interpreted?
  • WITH: (Policy) Which logic and constraints apply?
  • TO: (Contract) What the expected output format must be?
  • INTO: (Delivery) Where the final results are routed?

Design Merits

Principle Builder Signal Benefit
Intent-First Composition from... -> of... -> with... -> to... -> into... Makes purpose obvious at code review time and lowers onboarding cost.
Staged Safety Builder stages constrain what can be called next Reduces invalid pipeline shapes and catches mistakes before runtime traffic.
Deterministic Semantics Stable stage order and lifecycle contract Cross-language implementations can stay behaviorally equivalent.
Progressive Specificity Optional filters and writers compose without breaking core shape The same model scales from simple reads to advanced relay and extraction workloads.

The Power of a "Staged" Fluent Domain Specific Language

Each stage exposes only the valid next methods. Fluent chaining therefore guides composition in-order and blocks invalid transitions by construction.

This staged shape is what makes pipeline declarations reviewable, safer to compose, and easier for both humans and AI tooling to reason about.

Why This Helps Agentic Development

Low-Ambiguity Planning

Agents can infer intent from stage verbs directly, which improves automated planning and patch precision.

Bounded Search Space

Staged APIs narrow valid next moves, making tool-assisted composition more reliable and less error-prone.

Explainable Output

The pipeline declaration doubles as an execution narrative that both humans and AI systems can explain and audit.

Expressive DICOM® orchestration with clear, understandable intent

Real-world use case: de-identify and transcode before relaying to an outbound DICOMweb™ endpoint.

This declaration is readable as a contract, not just an implementation detail. 

sourceUrl := "https://pacs.example.org/dicom-web/studies/{studyUID}/series/{seriesUID}/instances/{instanceUID}"
destinationUrl := "https://relay.example.org/dicom-web/studies"

relayPipeline := EASI.pipelineBuilder()
  .fromHttpStream()
  .ofDicomData()
  .withDeIdentification(Tag.DefaultDeIdentificationMask)
  .withTranscoding(TransferSyntax.ExplicitVRLittleEndian.ID)
  .toDicomData()
  .intoHttpStream()
  .build()

writeResults := relayPipeline.process(sourceUrl, destinationUrl)
writeResult := writeResults.first()
if (writeResult == null) OR (writeResult.bytesWritten <= 0):
  fail("Expected normalized outbound DICOM bytes")

Real-world use case: de-identify and transcode before relaying to an outbound DICOMweb™ endpoint.

source_url = "https://pacs.example.org/dicom-web/studies/{studyUID}/series/{seriesUID}/instances/{instanceUID}"
destination_url = "https://relay.example.org/dicom-web/studies"

relay_pipeline = (
    EASI.pipeline_builder()
    .from_http_stream()
    .of_dicom_data()
    .with_de_identification(Tag.default_de_identification_mask)
    .with_transcoding(TransferSyntax.explicit_vr_little_endian.id)
    .to_dicom_data()
    .into_http_stream()
    .build()
)

write_results = relay_pipeline.process(source_url, destination_url)
write_result = write_results.first()
if (write_result is None) or (write_result.bytesWritten <= 0):
    raise RuntimeError("Expected normalized outbound DICOM bytes.")
